# Validation

Evidence that the [IA-32 model](../x86_32/README.md) behaves like real x86, plus the hardware tests for both models. `x86run` boots Linux, `x86test` replays test vectors, `x86sys` runs the system tests, and `x86litmus` explores concurrent executions; nothing here is imported by the model or its proofs.

```
$ lake build
$ ./verify.sh [N]    # N random QEMU tests, the Linux boot and the workload comparison
```

`x86run` options: `--mem MB`, `--max N` (instruction limit), `--expect PAT --send TEXT` (scripted input; `@exit` stops) and `--trace-from N --trace-count K` (register trace on stderr).

## QEMU differential tests
`test/run.sh N SEED` generates N random single instructions with random prefixes, operands, registers, flags, segment selectors and page-table bits, including page-crossing operands and single-stepping. A small kernel (`test/harness/`) runs each one under `qemu-system-i386` in ring 3. `x86test` then runs the same instruction on the model and compares the exception, CR2, registers, flags, selectors, a memory hash and the page-table entries, and (vector format v2) MXCSR, XMM0–7 and the YMM upper halves. QEMU emulates an EPYC-Rome (Zen 2) CPU minus what TCG lacks (`test/qemu-cpu.sh`); instruction forms it executes that the model does not implement yet are listed in `test/isa_forms.py` and not generated. Encodings that are #UD on Zen 2 (unassigned 0F 38/0F 3A/VEX opcodes, VEX after 66/F2/F3/LOCK, unknown VEX maps, EVEX/XOP register forms) are generated, also padded to the 15-byte limit; TCG raises #UD for a 16-byte unassigned encoding without fetching its last byte, where the model (SDM vol. 3, table 6-2) raises #GP(0), and `x86test` counts these separately. Extending the tests: `../x86_32/EXTENDING.md`.

AES-NI, PCLMULQDQ and SHA vectors (`test/gen_crypto.py`, about 18% of a run; register and memory operands, every imm8, misaligned AES/PCLMULQDQ operands, LOCK) are also checked against an independent reference, `test/cryptoref.py`, written from FIPS-197, FIPS 180-4, the GCM specification and the SDM instruction pages (its self-test checks the published vectors and `hashlib`): `run.sh` prints how many of QEMU's results it checked. TCG deviations: it runs the "NP" SHA instructions with a 66/F2/F3 prefix (the model raises #UD; `qemuAsHardware` accepts the model's #UD for those 'ud' vectors) and does not check the alignment of SHA memory operands (exception class 4 requires it; misaligned SHA operands are not generated, the system tests cover them).

So far 800,000 tests have shown 0 mismatches, covering 226 one-byte and 106 two-byte opcodes.

The general-purpose Zen 2 extensions (POPCNT, LZCNT, TZCNT, BMI1/BMI2 including VEX.L = 1, VEX.W and every pp/ModRM.reg neighbour, ADCX/ADOX, MOVBE, CRC32, PREFETCH/PREFETCHW, RDPID, CLFLUSH/CLFLUSHOPT/CLWB with paging off, and the #UD/#GP forms of RDRAND/RDSEED, RDPMC, MONITOR/MWAIT and MCOMMIT) are the 'ext' family of `test/gen_gpr.py` (about 18% of the vectors). Their results are also checked against `test/gpr_ref.py`, a reference written from the APM/SDM (the CRC32 polynomial division, PDEP/PEXT bit by bit, the published SplitMix64 for RDRAND), which runs the model through `x86test --dump` (`python3 test/gpr_ref.py check`, also a unit test). Not compared with QEMU, because TCG lacks them or has no defined value: RDRAND/RDSEED/RDTSCP/RDPRU results, CLZERO, MONITORX/MWAITX, RDPRU, WBNOINVD at CPL 3, CLFLUSH page faults and accessed bits (TCG makes no access), RDPID/RDTSCP with a 66 prefix (TCG writes 16 bits).

The system forms of workstream A (SYSCALL, SYSRET, SYSENTER, SYSEXIT, CLAC, STAC and LOCK MOV CR, with random prefixes) are the 'ext' family of `test/gen_sys.py` (about 2% of the vectors); at CPL 3 in the harness they check the #UD/#GP rules. TCG checks SYSRET's CPL before EFER.SCE (#GP instead of the APM's #UD): `x86test` accepts the APM's order (`qemuAsHardware`). `x86test` fails when not every vector of the input was compared (a stale harness or a record-size mismatch).

AVX (`x86_32/X86/Ext/Avx.lean`, `Vex.lean`) is the 'ext' family of `test/gen_avx.py` (about 10% of the vectors, every AVX form in VEX.128 and VEX.256, two- and three-byte VEX, register and memory operands with all addressing modes, misaligned and page-crossing operands, a tenth of them breaking one encoding rule: VEX.L, VEX.W, VEX.vvvv, ModRM.mod or reg); YMM upper halves are compared. `isa_forms.py` rows carry VEX.L and VEX.W, so the 'ud' family tests every undefined VEX neighbour (prefix, L, W, mod, reg) as #UD; the AVX2/FMA/F16C forms stay in NOT_YET_IMPLEMENTED (owner Avx2). TCG deviations accepted by `qemuAsHardware` (`tcgVexUd`, citing the manuals): TCG executes the VEX-prefixed MMX forms (VEX.pp = 00 of the MMX opcodes, SSSE3 0F 38 00..1E, PALIGNR), legacy-only forms with VEX (66 0F 38 10/14/15, F3/F2 0F 2B, VEX.66/F3/F2.0F 77), VEX.L = 1 of VMOVD r/m32 and VMOVLPx/VMOVHPx stores, and the register forms of VMOVLPD/VMOVHPD/VMOVNTDQ/VMOVNTPx, all #UD on the CPU (also when TCG's #UD comes after a memory access that set an accessed bit); it raises #UD for VEX.L = 1 of the LIG scalar forms; it loads 32 bytes for the m128 source of VCVTDQ2PD/VCVTPS2PD ymm (a #PF at the next page's first byte); and its masked stores (VMASKMOVPS/PD, VMASKMOVDQU) write the selected elements before a #PF on a later one, where the model, like every faulting instruction, leaves memory unchanged (only the hash is replaced). VMIN/VMAX are generated with MXCSR.DAZ clear (TCG returns the unflushed denormal). Not generated (covered by the system tests): VEX.L = 1 of VMOVSS/SD and VCVTSI2Sx (TCG keeps bits 255:128), of VROUNDSS/SD (QEMU 11.1.2 aborts in `gen_VROUNDSx`), VEX.NP.0F C4 (QEMU aborts in `gen_pinsr`), is4 with imm8[7] = 1 (TCG uses it as a register bit), VRCPPS/VRSQRTPS (implementation specific), two NaN sources, and VMASKMOVPS/PD loads with paging (TCG loads masked-out elements).

QEMU deviates from the Intel manual in a few places, which are not generated: AAM/AAD with an immediate ≥ 0x80, INVD/WBINVD at CPL 3, REP INS/OUTS with a zero count, REP with TF, and the read order of CMPS. Where QEMU deviates from hardware, `x86test` accepts the hardware behaviour and counts the case separately: page faults on read-modify-write operands (QEMU drops the W bit and sets A instead of A and D), and PUSHA, which QEMU probes as a whole instead of pushing in order.

## System tests
`test/sys/run.sh` builds a small multiboot test kernel (`test/sys/*.c`, clang only) and runs it under `qemu-system-i386` (the long-mode pass under `qemu-system-x86_64`, below) and on the model (`x86sys`), then compares the two serial transcripts line by line. It exercises what the single-instruction tests cannot: legacy and PAE paging with NX, debug-register breakpoints and RF, call gates, hardware task switches (including #DF through a task gate), virtual-8086 mode, the local APIC system-management mode, and the x87 FPU: 2,500 random operations over every operand class (denormals, pseudo-denormals, unnormals, NaNs, extreme exponents) with random rounding and precision control are compared with QEMU's softfloat, and stack faults, unmasked responses, #MF/FERR#, FIP/FDP/FOP and the C1 round-up indicator, which TCG does not model, are model-only checks (the kernel opens SMRAM and enables APM SMIs through QEMU's i440FX/PIIX4 chipset; the model has no chipset and `x86sys` starts with the firmware's SMBASE). MMX/SSE/SSE2 (`t_simd.c`, `t_simdx.c`): 6,500 random instructions (every MMX, SSE and SSE2 opcode and prefix form, register and memory operands, binary32/64 operands from every class, random RC/DAZ/FTZ and sticky flags with all exceptions masked) compared with QEMU (the EPYC-Rome CPU of `test/qemu-cpu.sh`; probes of SSE3 instructions follow CPUID), plus the #UD/#NM rules (CR0.EM/TS, CR4.OSFXSR), 16-byte alignment, undefined prefix combinations, prefix precedence, LDMXCSR/FXRSTOR reserved bits, the FXSAVE image and FXRSTOR; unmasked SIMD exceptions (#XM/#UD and their MXCSR flags), #MF for MMX instructions, the MMX exponent word, the two-NaN rule, MIN/MAX with DAZ, RCP/RSQRT special cases and FXSAVE's FIP/FDP are model-only (TCG returns the larger-significand NaN like x87 instead of the first operand, so two-NaN lanes are not generated for the QEMU comparison).

SSE3, SSSE3, SSE4.1, SSE4.2, SSE4a and MisalignSse (`x86_32/X86/Ext/Sse.lean`) are tested in every layer. The random single-instruction tests generate all their legacy forms (`test/gen_sse.py`, a third of the vectors; rows in `isa_forms.IMPLEMENTED` are the exact forms, so the neighbouring undefined prefixes and opcodes are tested as #UD). FP forms whose result would depend on the two-NaN rule are generated with at most one NaN input (TCG uses the larger-significand rule). `t_simd.c` runs every form in its `xops` table; `t_sse.c` fuzzes PCMPxSTRx (all imm8 modes, explicit and implicit lengths, unaligned memory), EXTRQ/INSERTQ (including the undefined index + length > 64 cases), PEXTR*/PINSR* with general registers, BLENDV and FISTTP against QEMU, and checks #UD/#NM/#GP rules. TCG deviations (rules in `qemu-deviations.txt`): EXTRQ/INSERTQ run with CR4.OSFXSR = 0 or CR0.EM = 1 (#UD in AMD APM vol. 4), and FXSAVE writes MXCSR_MASK 0xFFFF (TCG lacks MisalignSse). MisalignSse (MXCSR.MM, its alignment and #AC rules, CPUID 8000_0001:ECX[7]), unmasked exceptions of ROUND*/DPPS/HADDPS and FISTTP stack underflow are model-only. `test/sse_ref.py check out/model.txt` recomputes the PCMPxSTRx, EXTRQ/INSERTQ, FISTTP, ROUND*, DPPS/DPPD and MPSADBW lines with an independent reference (exact rational arithmetic, written from the APM/SDM; `test_sse_ref.py` has the APM's worked examples). The native campaign has families `sse3_*`, `ssse3`, `sse41_*`, `sse42_*`, `sse4a` and `misalign_sse` (`fp_cases_sse.py`); the cases whose hardware result the manuals leave open are marked 'observe'.

The x87 transcendental instructions are checked against an exact reference, `test/sys/x87ref.py`, written independently of the model (Python's `decimal` module, whose exp, ln and sqrt are correctly rounded, atan by argument halving, a different interval-rounding test). F2XM1, FYL2X, FYL2XP1 and FPATAN, which QEMU implements carefully in softfloat, are fuzzed against QEMU (3,000 cases with random rounding and precision control and every operand class). For every line where QEMU's result differs, `x87ref.py qemu out/qemu.txt` decides it and writes a per-line rule with its reason to `test/sys/x87t-deviations.txt` (it also measures QEMU's error in ulps against the SDM bound of vol. 1, 8.3.10). All 3,000 values agreed; the 231 rules record that TCG never reports the denormal-operand exception for these instructions (#D is in their SDM exception lists) and two NaN choices (QEMU takes ST(0); the SDM's table 4-7 takes the larger significand). The model must then match the corrected transcript. QEMU computes FSIN, FCOS, FPTAN and FSINCOS with host doubles, so for them (and to check C1, C2 and the stack effects of all eight, which TCG does not model) `x87ref.py table x87t_cases.h` generates 1,540 inputs with expected results, including arguments next to multiples of π/2 up to 2^62, tiny, huge, out-of-range and special operands; the test kernel compares them in the MODEL-ONLY section. Regenerate both files with `x87ref.py` after changing `t_x87t.c`.

`t_xsave.c` checks the XSAVE feature set against QEMU: CPUID leaf 0xD and the OSXSAVE mirror, the XSETBV/XGETBV rules, #UD/#NM/#GP/#PF conditions (page-crossing areas, read-only pages, ring 3), NP prefixes and neighbouring register forms, and `xsf` (default 500) random XSAVE/XSAVEOPT/XRSTOR cases with random XCR0, EDX:EAX masks, state and memory and corrupted standard headers (all components in use, because TCG tracks no XINUSE). Four TCG deviations are rewritten (`qemu-deviations.txt`: no #NM with CR0.TS, MXCSR not saved or loaded for RFBM = {AVX}, leaf 0xD subleaves for components its CPU lacks, XSETBV at CPL 3 with OSXSAVE = 0 raising #GP instead of #UD); TCG also does not write FOP and zeroes the padding of the x87 register slots: the random cases preset FOP and the hashes leave the padding out. Model-only (TCG has no XSAVEC/XSAVES/XRSTORS): the compacted formats, XINUSE and XGETBV(1), the init and modified optimizations, the error pointers, IA32_XSS, segment limits, and 600 cases of every instruction of the family generated with their expected results by `test/sys/xsaveref.py`, an independent reference written from the SDM pseudocode and the APM (`xsaveref.py table 600 1 > xsave_cases.h`). The random single-instruction tests set CR4.OSXSAVE and XCR0 = 7 now that the model implements XSAVE, and generate the XSAVE forms and their undefined neighbours (`test/xsave_gen.py`, 'ext' family). The native campaign has XSAVE/XSAVEOPT/XSAVEC/XRSTOR/XGETBV families (`test/native_xsave.py`, memory kind 4: images compared without reserved bytes and MXCSR_MASK) and reports how many rows could not compare the YMM upper halves.

`t_gpr.c` checks the general-purpose extensions: MONITOR/MWAIT privilege and ECX rules and an MWAIT woken by a pending interrupt, TSC_AUX with RDTSCP/RDPID and CR4.TSD, RDRAND/RDSEED flags and #UD forms, RDPMC at CPL 3, WBNOINVD, prefetches and the cache-line instructions; two TCG deviations are rewritten (`qemu-deviations.txt`: RDMSR of TSC_AUX reads 0 in qemu-system-i386, WBNOINVD runs at CPL 3). Model-only: CLZERO, MCOMMIT with EFER.MCOMMIT, RDPRU, RDPMC counters and CR4.PCE, HWCR.MonMwaitUserEn, reserved TSC_AUX bits, MWAIT with ECX[0] and without an armed or with a modified monitor line, MONITORX/MWAITX and the timed wait, and the page-fault, accessed-bit and segment-limit checks of CLFLUSH/CLWB/MONITOR/CLZERO. The native hardware campaign has `test/gpr_cases.py` families (registered in `fp_cases.FAMILIES`) for all user-mode forms, including the open questions (RORX with VEX.vvvv ≠ 1111b, RDPRU's CF for unsupported registers, the undefined flags kept in the raw rows).
AES-NI, PCLMULQDQ and SHA (`t_crypto.c`): the #UD/#NM/#GP rules of every instruction (CR4.OSFXSR, CR0.EM/TS, alignment, LOCK, every wrong mandatory prefix), FIPS-197 AES-128/192/256 encryption and decryption with AESKEYGENASSIST key expansion, the FIPS 180-4 "abc" digests and GCM test case 2 computed with the instructions are compared with QEMU (one rule in `qemu-deviations.txt` for TCG's SHA prefix and alignment deviations); 640 random cases with results from `test/cryptoref.py` (`sys/crypto_cases.h`) are a model-only table; the `xops` rows of `t_simd.c` fuzz all fourteen instructions against QEMU. The native campaign has AES, PCLMULQDQ and SHA families (`test/native_crypto.py`), including every imm8 of PCLMULQDQ, AESKEYGENASSIST and SHA1RNDS4 and, as observations for review, misaligned and 66/F2/F3-prefixed SHA forms.

Two more fuzzers cover paging and debug breakpoints (400 cases each by default; `pgf=N`, `dbf=N` on the command line). The paging fuzzer (`t_pgfuzz.c`) builds fresh page tables in each case, in 32-bit paging with or without CR4.PSE or in PAE paging with EFER.NXE on or off, with CR0.WP at random. The tables map an eight-page window of 4 KiB pages and sometimes a 4 MiB or 2 MiB page, onto a pool of frames, with random P, R/W, U/S, PWT, PCD, A, D, G, PAT and XD bits and occasional reserved bits. It then makes 3 to 8 accesses: reads and writes of 1, 2 or 4 bytes and instruction fetches, from ring 0 and ring 3, often across a page boundary. Each access prints its vector, error code, CR2 and the value read, or the bytes written. Every case ends with the accessed and dirty flags of each entry. The breakpoint fuzzer (`t_dbfuzz.c`) programs DR0 to DR3 and DR7 at random, with every R/W type and length, L/G enables and CR4.DE, and sometimes sets EFLAGS.TF. It then runs one load, store, read-modify-write, MOVS, PUSH or POP (memory or register), IN or OUT in ring 0 or ring 3, and prints DR6, the EIP and the RF image of every #DB. TCG reports only the first watchpoint that matches, and it splits a single-step trap and a data breakpoint on the same instruction into two #DBs, the second at the handler's first instruction. So `dbf` keeps only one matching data or I/O breakpoint and drops TF in such cases. The model-only `dbfm` runs the same generator without these exclusions and checks every #DB against an expectation computed in C (SDM 17.2.3, 17.3.1). The paging fuzzer found that the model did not set the accessed flag of a page-directory entry when the walk used it but the page-table entry then faulted (SDM 4.8). It also showed that 4 MiB PDEs lacked the reserved-bit check for bits 21:13 when CPUID reported no PSE-36; the model now implements PSE-36 (bit 21 reserved), like TCG.

System workstream A (`t_sysa.c`, `t_pae.c`, `t_pgfuzz.c`): SYSENTER/SYSEXIT and SYSCALL/SYSRET between ring 3 and ring 0 (selectors, flags, stacks, the null-selector, CPL and EFER.SCE faults), CLAC/STAC, UMIP, AltMovCr8 (LOCK MOV CR0 = CR8 and the APIC's TPR), the EFER bits, MSR round trips (SYSENTER, STAR, PAT, MTRRs), PSE-36 (bits 20:13 of a 4 MiB PDE address memory above 4 GiB; bit 21 is reserved), SMEP and SMAP with translations cached before CR4 changes, and SMAP for an implicit access (an LDT on a user page, loaded with EFLAGS.AC = 1). The paging fuzzer also randomises CR4.PGE, PSE-36 address bits and, in about half of its cases, runs on a supervisor identity map with random CR4.SMEP/SMAP and random EFLAGS.AC for ring-0 accesses (its ring-3 snippets are copied to user pages); PAE reserved bits are generated above MAXPHYADDR = 48 only. TCG deviations, rewritten by rules citing the APM: SYSCALL/SYSRET clear or force the RPL of SS, CR8's reserved bits are ignored, reserved EFER/PAT/MTRRdefType bits are accepted, EFER.LMSLE/FFXSR/TCE/INTWB are dropped, PAE address bit 40 is reserved (fewer physical-address bits), and AC overrides SMAP for implicit accesses (the newer Intel rule). Model-only (`model-only.expected`): alignment checking (TCG has none; 50 operand forms incl. x87 environment/save areas, SSE, CMPXCHG8B, far pointers, SGDT, the exempt cases and #AC before #PF), global pages across MOV CR3/INVLPG/CR4.PGE (retention is implementation-defined), the TSC MSR (TCG ignores MSR 0x10), and the MCA, MTRR, LSTAR/CSTAR, SPEC_CTRL/PRED_CMD and AMD configuration MSRs. `pgfm.pse.rsvd` now checks PSE-36: bits 20:13 reach (absent) memory above 4 GiB, bit 21 faults.

AVX (`t_avx.c`, plus 270 VEX rows in the `xops` table of `t_simd.c`, every row run at least once with VEX.L random where it applies, VEX.vvvv = XMM2 or 1111b per row, YMM upper halves loaded and printed): the #UD/#NM matrix (CR4.OSXSAVE, XCR0 = 1/3, CR0.TS, CR0.EM, CR4.OSFXSR, prefixes before VEX, unknown maps, VEX.W/VEX.L/VEX.vvvv/ModRM.mod rules), alignment of the class-1 moves (16/32 bytes) and unaligned operands of every other class, VEX.128 zeroing against legacy SSE, VZEROUPPER/VZEROALL, VMASKMOVPS/PD next to a not-present and a read-only page, VLDMXCSR/VSTMXCSR, VEX in a 16-bit protected-mode code segment (QEMU 11.1.2 decodes VEX there as the SDM requires), and 1500 `avxk` cases of the AVX-only shuffles/permutes/broadcasts/masked moves/blends/tests and the 32 VCMP predicates, which `test/avx_ref.py check` recomputes with an independent reference (`test_avx_ref.py`). Rules in `qemu-deviations.txt`: TCG raises #UD for VEX instructions with CR0.EM = 1, #NM instead of #UD for VEX.W = 1 with CR0.TS, faults on masked-out VMASKMOV load elements and loads reserved MXCSR bits with VLDMXCSR. Model-only (`avxm.*`): VEX.L = 1 of the LIG scalar forms, is4 imm8[7], MXCSR.MM with VEX, unmasked #XM and #UD (OSXMMEXCPT = 0), #AC with VEX operands, #UD before #NM. The native campaign has families `avx_ops`, `avx_encoding`, `avx_maskmov` and `avx_alignment` (`test/native_avx.py`, requiring `avx`, `osxsave`).

Where QEMU's TCG deviates from the Intel SDM, the rules in `test/sys/qemu-deviations.txt` rewrite the QEMU line to the SDM-defined result before comparing; each rule states the SDM section. Examples: reserved-bit page faults have P = 1, MOV SS delays debug traps past the next instruction, data breakpoints in REP instructions trap after the matching iteration, and a fault after a task switch commits is raised in the new task. Behaviour that TCG cannot run at all (the TSS T flag) comes after a `MODEL-ONLY` marker and is checked against `test/sys/model-only.expected`.

Control transfers (`t_xfer.c`) are fuzzed too: `tsf=N` hardware task switches (JMP/CALL to a TSS or a GDT/LDT task gate, INT n through an IDT task gate and IRET with NT, from ring 0 or 3, to 32- and 16-bit TSSs with random limits, busy and present bits, DPLs, segment and LDT selectors, EFLAGS including NT and VM, EIPs beyond the limit and previous-task links), and `cgf=N` far CALL/JMP directly or through 16- and 32-bit call gates (random DPLs, parameter counts, targets and inner stacks in the TSS, from rings 0 to 3) and far RETs to outer levels with random CS/SS and data segment registers (default 300 cases each). Every exception and the end of each case go through IDT task gates to recovery tasks, so the outcome (vector, error code, the task it was raised in, the new task's registers as saved in its TSS, the inner-stack frame) is observed from a clean task even after TCG has delivered a fault with the old task's EIP. The fuzzers found six model bugs: JMP/CALL to a TSS descriptor in the LDT switched tasks instead of raising #GP; an IRET to the current task loaded the TSS contents from before the switch saved the state; null selectors with RPL > 0 survived returns to outer levels; RETF to a 16-bit stack cleared ESP[31:16]; an inner-stack selector beyond the table limit raised #GP instead of #TS; and a call gate whose inner stack had no room for the frame raised #SS(0) after the offset check instead of #SS(new SS) before it. TCG deviations handled by rules: #TS for TSS selectors with TI = 1, #NP/#TS for not-present stack segments, CS.RPL = DPL after a CALL through a gate to a conforming segment; by exclusion with model-only checks: conforming task CS with DPL < RPL, offset checks of far CALLs and RETs, JMP through a gate to a not-present segment, inner-stack limits and ESP[31:16] of 16-bit inner stacks (TCG keeps the caller's), null FS/GS on returns, RF in the EFLAGS image of faults through task gates and the EIP of faults after the task-switch commit point.

Long mode (`t_long.c`) is a second pass of `test/sys/run.sh` with the command line `long=1` under `qemu-system-x86_64` (the EPYC-Rome CPU of `test/qemu-cpu.sh` with long mode; `qemu-system-i386` has none). The kernel builds 4-level page tables and a 64-bit IDT, checks the activation rules from legacy mode (EFER.LME, PG without PAE, EFER.LMA writes), activates long mode and runs compatibility-mode code at CPL 0 and 3: 4-level paging (A/D bits at every level, 2 MiB and 1 GiB pages, NX at PTE/PDE/PDPE level and without NXE, reserved bits, bits 62:52, U/S and R/W across levels with CR0.WP, SMEP/SMAP, INVLPG of a 1 GiB page), interrupts and exceptions through 64-bit gates (IST, trap gates, the #GP/#NP rules for task gates, 16-bit gates, not-present gates and non-64-bit targets, INT n DPL from ring 3 with the RSP0 stack switch), SYSENTER/SYSEXIT/SWAPGS/RDFSBASE #UD, IRET with NT, FS_BASE/KernelGSbase, LTR/LLDT/LAR/LSL with long-mode descriptor types, 16-bit compatibility-mode code, and every transfer into 64-bit code: far JMP/CALL to a 64-bit segment and through 64-bit call gates (same privilege and from ring 3), RETF and IRET to 64-bit code, and SYSCALL to CSTAR. Exceptions in long mode go to 64-bit handlers and those transfers enter 64-bit code; their targets are tiny hand-assembled 64-bit stubs that record the frame (and RCX/R11) and return with IRETQ to compatibility mode. QEMU executes them; the model stops before the first 64-bit instruction, and `x86sys` applies the stub's exact effect (`LongStub.lean`, recognised by its bytes) and continues, so both transcripts show the architectural state at the boundary. A 4-level paging fuzzer (`lmf=N`, 300 cases by default; 1,500 cases each with seeds 7 and 99 checked) extends `t_pgfuzz.c` to random PDPEs (directories or 1 GiB pages), PDEs and PTEs with reserved bits, NX at every level, WP, NXE, PGE and SMEP/SMAP. TCG deviations, each rewritten by a rule citing the APM (`qemu-deviations.txt`, `lm.`/`lmf` rules): reserved-bit #PF with P = 0, 40 physical-address bits, MOV CR0 enabling paging with LME and PAE = 0 ignored instead of #GP, EFER.LMA writable and LME changeable with paging on, LTR reading 16-byte descriptors in compatibility mode, LAR/LSL with legacy types, SYSENTER/SYSEXIT executed in long mode, non-canonical FS_BASE/KernelGSbase accepted, a code segment with L = D = 1 entered, and the accessed bit of a 1 GiB or 2 MiB leaf set on a faulting access. Model-only (`model-only-long.expected`, after `MODEL-ONLY`; TCG would run 32-bit code as 64-bit code or walk 4-level tables as 32-bit ones): enabling paging with CS.L = 1, clearing CR4.PAE in long mode.

`x86bridge` (`BridgeMain.lean`, the only target that depends on both Lake packages) hands every stop of the IA-32 model in 64-bit mode to the `x86_64` model: it converts the machine state (registers zero-extended, RIP/RSP/R11 from `LongModeState`, segment caches, descriptor-table registers, control and debug registers, EFER and the SYSCALL/FS/GS MSRs, XMM, x87, memory; the state mapping is documented in the file) and runs the x86-64 model, which stops in turn at the first transfer back to compatibility mode (it has no compatibility mode). On `t_long` (`x86bridge --cmdline long=1 test/sys/out/systest.elf`) all 1,103 stops run the test's stub in the x86-64 model up to its IRETQ with exactly the memory writes and registers of `LongStub.lean`'s emulation.

## TSO memory-model tests

`lake build x86litmus` builds the concurrent execution explorer. Run
`python3 litmus/litmus.py check-expected litmus/tests litmus/diy` to compare all final states with
the pinned expected sets. The [litmus documentation](litmus/README.md) describes their provenance
and how to compare directly with herd7. `verify.sh` also checks that enabling the TSO access log
preserves single-CPU execution and records all stores, using 20,000 generated instruction vectors
(only those with paging off are checked).

## Hardware tests
For the IA-32 x87/MMX/SSE/SSE2 coverage gap, the new
[user-mode floating-point campaign](test/FP-HARDWARE.md) provides over 120,000
directed and random cases, a full-state native oracle, and a self-contained
Linux paste script. It requires no root, KVM, compiler or Lean on the target.
Preparation and emulator smoke checks are not physical-hardware evidence.
Its `alignment_check` family (`fp_cases.alignment_cases`, 547 cases) checks user-mode alignment
checking: Linux runs with CR0.AM = 1, so the oracle passes EFLAGS.AC as an input and #AC arrives as
SIGBUS (trap 17); it covers integer, string, x87 and SSE operands at offsets 0..12, the masked stores,
and a misaligned access to an unmapped page (#AC or #PF first). SYSCALL, SYSENTER, SMEP/SMAP, UMIP,
global pages and the MSRs cannot be tested natively in user mode.

The native oracle runs each case as 32-bit code in compatibility mode under 64-bit Linux. `x86fp --compat`
runs the cases that way on the model too (EFER.LME/LMA/NXE/SCE, CR4.PAE, 4-level page tables with the
same identity map and test pages, CS 0x23 with L = 0); by default x86fp keeps legacy protected mode.
On the 24 campaigns of `test/out/ia32-fp-hardware` (116,715 cases) both configurations give identical
output for every case (including the 3,034 page faults), and the legacy output is identical to the
stored `.model` files: no user-mode floating-point or SIMD instruction behaves differently in
compatibility mode, and the 4-level walk gives the same #PF error codes for these accesses.

These run on an x86-64 Linux server without root or KVM. Each instruction executes in user mode, and Linux signal handlers capture the result, for both models:

```
$ python3 test/native.py prepare test/out/run --count 20000 --seed 1    # or --memory, --hunt, --focused-sse
$ bash test/native_remote.sh test/out/run.tar.gz user@host
$ python3 test/native.py compare test/out/run-returned --prepared test/out/run
```

`--memory` adds loads, stores and read-modify-write operations on pages that are writable, read-only or unmapped. `--hunt` targets areas earlier runs missed, and `test/native_hunt.py` groups its mismatches. For privileged and paging behaviour, `test/hardware.py` runs the QEMU harness under KVM (`-accel kvm -cpu host`).

On an AMD EPYC 7742, about 475,000 observations across four campaigns now all match. Bugs found this way and by the Linux boot:
- AAS ignored the borrow out of AL.
- LOCK on non-lockable instructions did not raise #UD.
- Read-modify-write instructions skipped the write-back for a zero shift count and for an unchanged ARPL.
- Read-modify-write operands were translated as reads, giving the wrong page-fault error code.
- PUSHA and POPA restored the wrong state after a fault, and ENTER did not check its final stack byte.
- The second immediate of far pointers and ENTER re-read the first (found by the Linux boot).
- x86-64 SSE: wrong MXCSR flags with unmasked exceptions, and flush-to-zero at the underflow boundary.

Regression tests: `python3 test/rmw_regression.py` and `python3 test/stack_regression.py`.

## Linux guest
`guest/build.sh` builds Linux 6.12.111 from `tinyconfig` plus `guest/kernel.fragment`: a 486SX-class kernel with math emulation, an 8250 console and no SMP, APIC, PCI or ACPI. It also builds an initramfs with Debian's static i386 BusyBox. Run it in a Linux VM, e.g. on macOS:

```
$ limactl start --name=kbuild template:debian
$ limactl shell kbuild -- sudo apt-get install -y build-essential flex bison bc libelf-dev cpio lz4 gcc-i686-linux-gnu
$ limactl shell kbuild -- bash guest/build.sh
```

`guest/workload.sh` runs hashing, sort, a gzip round trip, shell arithmetic, floating-point awk (on the model's x87 FPU, which CPUID advertises), tmpfs I/O and `/proc` reads. Debian's BusyBox awk is built without its math library, so the transcendental instructions were checked in the guest with a small static test program instead (all results bit-identical to `test/sys/x87ref.py`). Its output on the model is byte-for-byte identical to QEMU's (`guest/workload.qemu.txt`).
