# IA-32

A model of 32-bit x86 as pure Lean definitions. The same definitions are what the proofs in `X86/Proofs/` are about and what gets compiled to boot Linux 6.12.111 (see [`../validation/`](../validation/README.md)). There is no separate emulator that could drift from the specification.

The CPU identifies as an i686-class Pentium Pro with an x87 FPU, MMX, FXSAVE/FXRSTOR, SSE and SSE2, debugging extensions, PAE, NX and a local APIC. Linux uses the model's FPU instead of its math emulator and, since the model reports XSAVE, saves it with XSAVES/XRSTORS in the compacted format (before: FXSAVE). Booting to the shell takes about 62M instructions (≈ 12 s).

## What's modelled
- The integer instruction set (≈ 330 opcodes), including BCD, string instructions with REP, CMPXCHG8B, CMOV, CPUID, RDTSC and MSRs.
- Segmentation, protection rings, interrupts and exceptions through the IDT, far control flow, port I/O with the TSS permission bitmap.
- Call gates (16- and 32-bit; inner-privilege calls switch stacks and copy parameters) and hardware task switching: JMP/CALL to a TSS or task gate, task gates in the IDT (as Linux uses for #DF), IRET with NT, 32- and 16-bit TSSs, busy/NT/link bookkeeping and the TSS T flag. A fault after the switch has committed is delivered in the new task.
- Virtual-8086 mode: entry by IRET or task switch, interrupts and exceptions to ring-0 handlers, IOPL-sensitive instructions, and the virtual-8086 mode extensions (CR4.VME) and protected-mode virtual interrupts (CR4.PVI): VIF/VIP, CLI/STI/PUSHF/POPF/IRET working on VIF with IOPL < 3 (with the #GP(0) rules for VIP and TF), INT n redirected to the 8086 handler through the TSS interrupt redirection bitmap (AMD APM vol. 2, 8.8-8.10, table 8-11); VIF and VIP are loaded by IRETD at CPL 0, IRET to virtual-8086 mode, task switches and RSM.
- Two-level paging (4 KiB and 4 MiB pages, A/D bits, CR0.WP) and PAE paging (PDPTE registers, 2 MiB pages, reserved-bit faults, execute-disable with EFER.NXE), with a 1024-entry TLB that software must flush, as on hardware.
- Debug registers: instruction, data and I/O breakpoints, single-step, general detect, RF, and debug traps held across MOV SS / POP SS (so `MOV SS; INT n` takes the #DB at the handler entry, the behaviour behind CVE-2018-8897).
- The x87 FPU (`X86/Float80.lean`, `X86/Fpu.lean`): exact 80-bit arithmetic with rounding and precision control, denormals, x87 NaN rules, masked and unmasked exception responses (wrapped exponents, #MF, FERR#), stack faults, loads/stores of all memory formats including BCD, compares, FPREM/FPREM1, FSCALE, FXTRACT, FRNDINT, constants, FCMOV/FCOMI, the environment and FNSAVE/FRSTOR formats, and FIP/FDP/FOP.
- The x87 transcendental instructions (`X86/Transcendental.lean`): F2XM1, FYL2X, FYL2XP1, FPATAN, FSIN, FCOS, FSINCOS and FPTAN return the correctly rounded value of the exact function in the current rounding mode, which is within the SDM's accuracy bounds (below 1 ulp, 1.5 ulps in directed modes; vol. 1, 8.3.10). The engine evaluates series in ball arithmetic (integer center and radius, each operation's error bound stated in the source) and rounds both ends of the enclosure, raising the working precision until they agree (Ziv's strategy); exactly representable results (2^±1 − 1, y·log2(2^k), the zero/infinity/π-multiple rows of the SDM tables) are computed directly, and exact elementary bounds (x − x³/6 < sin x < x, ...) keep tiny arguments cheap. FSIN, FCOS, FSINCOS and FPTAN reduce the argument exactly by Pi/2, where Pi is the SDM's 66-bit approximation 0.C90FDAA22168C234C·2^2 (vol. 1, 8.3.8), with the nearest quotient: |x| ≤ Pi/4 gives the correctly rounded sin x itself, larger arguments sin(x + k(π − Pi)/2), the behaviour the SDM describes as approximating sin(x·π/Pi). Operands with |x| ≥ 2^63 set C2 and leave ST(0) unchanged. Where the SDM leaves the result undefined (F2XM1 with |x| > 1, FYL2XP1 outside √2/2 − 1 ≤ x ≤ √2 − 1, AMD's documented range), the model follows QEMU: an invalid operation. FPTAN and FSINCOS put a NaN result in both destinations; FSINCOS sets C1 if either result was rounded up. An unmasked IE, DE or ZE stops any x87 instruction before the lower-priority overflow, underflow and precision exceptions are detected (vol. 1, 4.9.2).
- MMX, SSE and SSE2 (`X86/Simd.lean`, `X86/Float.lean`): MM0–7 aliased to the x87 registers (TOP = 0, tags valid, exponent word all ones; EMMS), XMM0–7 and MXCSR with exact binary32/binary64 arithmetic (rounding modes, DAZ, FTZ, all six exception flags, unmasked exceptions as #XM or #UD with the destination preserved), every packed-integer, move, shuffle, compare and conversion instruction, the mandatory-prefix decoding of the 0F map (undefined prefix combinations are #UD), 16-byte alignment checks, CR4.OSFXSR/OSXMMEXCPT, FXSAVE/FXRSTOR (MXCSR_MASK = 0x2FFFF, see MisalignSse below), LDMXCSR/STMXCSR, fences and non-temporal stores. RCPPS/RSQRTPS, whose exact results are implementation specific, are defined as the round-to-nearest values of 1/x and 1/√x with the SDM's special cases (see the module documentation).
- SSE3, SSSE3, SSE4.1, SSE4.2, SSE4a and AMD's Misaligned SSE mode (`X86/Ext/Sse.lean`; legacy encodings, the VEX forms are AVX's): every instruction of these extensions (FISTTP in the x87 code; CRC32/POPCNT and MONITOR/MWAIT belong to the GPR work), written as pure kernels on 128-bit values with explicit operands so that the AVX forms can reuse them. ROUND* uses an exact round-to-integral (`FP.roundToIntegral`: IE for SNaN, PE unless imm8[3], DAZ, no DE); DPPS/DPPD report exceptions stage by stage (VDPPS ymm: a stage spans both 128-bit lanes); HADDPx returns the higher element's NaN of a two-NaN pair (the first operand as the SDM and APM write the addition), HSUBPx the lower's; PCMPxSTRx implement all imm8 modes with the SDM's rules for invalid elements. MXCSR.MM (bit 17) lifts the 16-byte alignment #GP of legacy load/execute instructions (MOVAPx, MOVDQA, MOVNTPx, MOVNTDQ, MOVNTDQA, FXSAVE/FXRSTOR keep it) and raises #AC instead when alignment checking is on; MXCSR_MASK is 0x2FFFF; CPUID reports SSE3, SSSE3, SSE4.1, SSE4.2, SSE4A and MisAlignSse. Where the manuals leave results undefined the model chooses (documented in the module): EXTRQ/INSERTQ keep bits 127:64 and read bits above 63 as zero when index + length > 64 (as QEMU and Bochs), and the equal-ordered PCMPxSTRx mode follows the SDM where AMD's pseudo code differs (empty prototype, partial match at the end of a full-length string); real Zen 2 behaviour for these is recorded by the native campaign, not yet known.
- The general-purpose Zen 2 extensions (`X86/Ext/Gpr.lean`): POPCNT, LZCNT, TZCNT, BMI1 and BMI2 (VEX-encoded, with the VEX.L/pp/ModRM #UD rules), ADCX/ADOX, MOVBE, CRC32, RDRAND/RDSEED (a deterministic SplitMix64 entropy source that is machine state; they never fail), RDTSCP/RDPID with TSC_AUX, RDPMC (AMD PerfCtr MSRs that hold their value but do not count), RDPRU (MPERF/APERF counting at the TSC rate), CLFLUSH/CLFLUSHOPT/CLWB (the checks and accessed bit of a one-byte load; no caches), CLZERO, WBNOINVD, PREFETCH/PREFETCHW, MCOMMIT (EFER.MCOMMIT) and MONITOR/MWAIT/MONITORX/MWAITX: the monitor arms a 64-byte line, and MWAIT waits like HLT for an interrupt (with ECX[0] also for a masked one; MWAITX with its TSC timeout), but only while the line is unchanged; HWCR.MonMwaitUserEn allows MONITOR/MWAIT at CPL 3. Undefined flags and the other choices where the manuals are silent are listed in the module documentation.
- System extensions of Zen 2 (`X86/Ext/Sys.lean`, paging in `X86/Machine.lean`; AMD APM vol. 2/3): SYSENTER/SYSEXIT and the legacy-mode SYSCALL/SYSRET of AMD (EFER.SCE, STAR; SYSRET keeps SS's cached attributes and does not force its RPL), CLAC/STAC, SMEP and SMAP (implicit supervisor accesses to the GDT, LDT, IDT and TSS are checked regardless of EFLAGS.AC, as the APM says; also on TLB hits), UMIP (SGDT, SIDT, SLDT, STR, SMSW #GP(0) at CPL > 0), global pages (CR4.PGE: MOV CR3 and task switches keep G = 1 translations, INVLPG and CR0.PG/CR4.PAE/PSE/PGE changes, MTRR writes, SMM entry and RSM drop them), PSE-36 (4 MiB PDE bits 20:13 are physical-address bits 39:32) and MAXPHYADDR 48 for PAE reserved bits (memory above 4 GiB is open bus), alignment checking (#AC with CR0.AM and EFLAGS.AC at CPL 3, with the operand alignments of the APM's table 8-7 for integer, x87 and SSE operands, checked before paging; implicit accesses and instruction fetches are exempt), AltMovCr8 (LOCK MOV CR0 is CR8 = TPR[7:4]), EFER.FFXSR, TCE, LMSLE and INTWB (accepted; without effect in legacy mode), and the MSRs: TSC (0x10, writable; RDTSC and RDTSCP read it), SYSENTER and SYSCALL MSRs, PAT and MTRRs with their #GP rules (fixed-range RdMem/WrMem with SYSCFG), MCG_CAP/STATUS/CTL and 23 MCi banks, SPEC_CTRL (IBRS/STIBP/SSBD), PRED_CMD (IBPB), SYSCFG, IORRs, TOP_MEM/TOP_MEM2, NB_CFG, the watchdog timer, OSVW, the CPUID override MSRs (storage only), LS_CFG and DE_CFG. Values that need the family 17h PPR (MCA bank count, reset values and reserved bits of the AMD configuration MSRs) are marked UNCONFIRMED in the module.
- AES-NI (AESENC, AESENCLAST, AESDEC, AESDECLAST, AESIMC, AESKEYGENASSIST), PCLMULQDQ and the SHA extensions (SHA1RNDS4, SHA1NEXTE, SHA1MSG1, SHA1MSG2, SHA256RNDS2, SHA256MSG1, SHA256MSG2), legacy encodings (`X86/Ext/Crypto.lean`; CPUID reports AES and PCLMULQDQ; the SHA bit stays clear until SSSE3 is implemented, because software such as BusyBox's sha256sum selects SHA code that also uses PSHUFB by the SHA bit alone, but the SHA instructions execute). Each instruction is a pure function on 128-bit values, exported for the VEX forms. The SSE rules apply (CR0.EM/CR4.OSFXSR #UD, CR0.TS #NM, 16-byte alignment #GP(0)); a wrong mandatory prefix is #UD, including 66/F2/F3 on the "NP" SHA instructions (QEMU's TCG runs those; that Zen 2 raises #UD is not confirmed by hardware yet).
- Long mode (`X86/Ext/LongModeBase.lean`, `X86/Ext/LongMode.lean`, `walkLong` in `X86/Machine.lean`; AMD APM vol. 2 ch. 4, 5, 8, 14, vol. 3): EFER.LME with LMA = LME ∧ CR0.PG maintained by the processor, the consistency checks of table 14-5 (#GP(0) for PG with LME and PAE = 0 or CS.L = 1, for clearing PAE in long mode, for changing LME with paging on) and LMA read-only (a WRMSR that differs from it is #GP); 4-level paging with 4 KiB, 2 MiB and 1 GiB pages, NX, MAXPHYADDR 48, the long-mode reserved bits (bits 62:52 are available), A/D bits, U/S and R/W ANDed and NX ORed over the levels, SMEP/SMAP and global pages, in the same TLB (1 GiB pages are tracked for INVLPG); and compatibility mode for 32- and 16-bit code: 16-byte 64-bit IDT gates (IST, RSPn of the 64-bit TSS with a null SS, 16-byte-aligned 8-byte frames; task gates and 16-bit gates #GP), 64-bit call gates, no task switching (#GP for TSS/task-gate targets and IRET with NT), no virtual-8086 mode, returns to 64-bit code with a null SS, SYSCALL to CSTAR, SYSENTER/SYSEXIT/SWAPGS/RDFSBASE.. #UD, LTR/LLDT with 8-byte descriptors and the long-mode types of LTR/LAR/LSL, FS_BASE/GS_BASE/KernelGSbase. CPUID reports LM, Page1GB, LahfSahf and FSGSBASE (not CMPXCHG16B: a 64-bit-mode instruction the x86-64 model lacks). **The 64-bit boundary**: the model executes no instruction in 64-bit mode (CS.L = 1 with LMA, theorem `execInstr_64bit`); every transfer into 64-bit code (far JMP/CALL/RET, IRET, SYSCALL, every interrupt or exception in long mode) is executed completely, with all its checks and stack writes, and the next step stops with `Fault.unsupported "64-bit mode"` at the first 64-bit instruction, with RIP/RSP bits 63:32 and R11 in `LongModeState`: a complete 64-bit state that `validation/BridgeMain.lean` hands to the x86-64 model. Returns to 64-bit code load the full popped RSP (+ RETF's immediate) whatever SS.B, and a same-privilege CALL through a 64-bit call gate pushes on the flat 64-bit stack at RSP (the APM's CALLF pseudocode pushes after CS is loaded). Debug breakpoints: DR0–DR3 hold 32-bit addresses, so stack slots at or above 4 GiB match none, and the instruction-breakpoint check of the first 64-bit instruction is left to the 64-bit executor. Not modelled: a #PF on a 64-bit stack above 4 GiB (CR2 is 32 bits; the model stops).
- System-management mode: SMIs through the APM control port (0xB2; to the CPU executing the OUT — which CPUs a real chipset signals is open), the AMD64 SMRAM state-save map of AMD APM vol. 2, table 10-1, which AMD64 processors use in every mode (with EFER, so SMIs are taken in long mode too), SMM entry with EFER = 0, RSM with the shutdown checks of 10.4 and EFER.LMA = LME ∧ PG ∧ PAE recomputed, SMBASE relocation (SMRAM protection is the chipset's and is not modelled).
- NMI, exception classes and IRPerf (system workstream B, `X86/Ext/SysB.lean`, `X86/Step.lean`): the NMI latch (one pending NMI per CPU, `Cpu.latchNmi`, fed by every NMI source of the APICs at the destination CPU's next instruction boundary: NMI IPIs, LVT and I/O APIC entries in NMI mode; plus a model-only test MSR enabled by `x86sys` for delays the APIC cannot express), delivery through vector 2 (interrupt, trap or task gate; HLT wakes), blocking from delivery until an IRET completes (AMD APM vol. 2, 8.1.4: a faulting IRET leaves NMIs blocked, unlike the Intel SDM) and in SMM (RSM restores the blocking state, an IRET in SMM unblocks), held in the MOV SS/STI shadow; events at an instruction boundary in the priority order of AMD's table 8-9 (SMI, debug traps, NMI, INTR, then the instruction; `Step.nextEvent`); the double-fault classes of AMD's tables 8-2/8-3 (benign events are handled serially, contributory + contributory and page fault + contributory/page fault give #DF, anything while delivering #DF shuts down) and the EXT bit of error codes for faults while delivering exceptions, interrupts and INT1; the instructions-retired counter IRPerfCount (C000_00E9h, HWCR.IRPerfEn) with HWCR.McStatusWrEn (bit 18) honoured by the MCi_STATUS MSRs; MSR 8Bh is read-only (#GP on WRMSR) with the AMD identity (PATCH_LEVEL) and stays writable with the legacy Intel identity, where Linux writes it while booting.
- PIC, PIT, UART, CMOS RTC and the Linux 32-bit boot protocol (with MP tables for `--smp`).
- The multiprocessor platform (`X86/Dev.lean`, `Machine.lean`, `Io.lean`, `Mp.lean`, `Ext/Smp.lean`; AMD APM vol. 2, chapter 16): a local APIC per CPU with every message type for IPIs, I/O APIC entries and LVT entries (fixed, lowest priority with AMD's APR arbitration, focus processor and highest-ID tie break, SMI, NMI, INIT and INIT de-assert, STARTUP, ExtINT, remote read), physical, logical flat and cluster destinations and all shorthands, ESR with SAE/SIV/RIV/IRA and the error interrupt, APR, the one-shot and periodic timer (no TSC-deadline mode on Zen 2), LINT0 in every mode (the PIC through LINT0 in ExtINT mode is the reset virtual wire), the AMD extended APIC space (extended feature/control registers, SEOI, IER, four extended LVTs as storage), IA32_APIC_BASE (relocation, global disable, BSC) and x2APIC mode (the APM's mode transitions, MSRs 800h–8FFh with their read-only, write-only and reserved-bit #GP rules, 64-bit ICR, SELF IPI, 32-bit and derived logical IDs, MMIO page disabled); an 82093AA I/O APIC at 0xFEC00000 (24 entries, edge/level, polarity, remote IRR and EOI messages from the local APICs) to which the PIT, UART and RTC lines are routed as well as to the PICs, whose virtual-wire mode is unchanged; INIT (the INIT state of APM table 14-1, every field listed in `Cpu.afterInit`), wait-for-SIPI and STARTUP (accepted also while an INIT is still pending, so back-to-back INIT/STARTUP work whatever the schedule); application processors start from the RESET state (CR0 = 6000_0010h, x87 CW 0040h/TW 5555h), which INIT keeps; NMI, INIT, SMI and ExtINT entries of the I/O APIC are edge-triggered whatever their trigger bit (82093AA); TMR changes only on acceptance; lowest priority compares APR bits 7:4; at most 128 CPUs (one 7742 package), the I/O APIC ID is N for N ≤ 14, else 0; and `MpMachine`, N CPUs with their own `Cpu`, APIC and TLB on shared memory and devices, run by a deterministic round-robin scheduler (see below). CPUID reports x2APIC, HTT, CmpLegacy, ExtApicSpace and TopoExt and the topology of N CPUs (leaf 1 EBX, 0Bh, 8000_0008 ECX, 8000_001D/1E: the first N threads of a 7742 package, `Cpuid.topo`; for N = 1 HTT and CmpLegacy are 0, APM vol. 3 table E-5). NMI delivery is a placeholder (vector 2, no blocking until IRET) until the NMI architecture of system workstream B is merged. Choices where the APM is silent or inconsistent are listed in `X86/Dev.lean` (e.g. SVR.FCC, XAIDN, IER writes, SAE).
- Deterministic virtual time: a nominal 100M instructions per second, with HLT skipping to the next timer event.
- AVX (`X86/Ext/Vex.lean`, `X86/Ext/Avx.lean`): YMM0–7 (`SseState.ymmh` holds bits 255:128) and every AVX (AVX1) instruction of Zen 2 in 32-bit mode — the VEX.128 and VEX.256 forms of the SSE..SSE4.2 instructions (VEX.128 only for the integer ones; their VEX.256 forms are AVX2), three-operand scalar forms with the VEX.vvvv merge, the 32 VCMP predicates, VEX conversions and moves, VLDMXCSR/VSTMXCSR, VEX.128 AES-NI and VPCLMULQDQ (Zen 2 has no VAES and no 256-bit VPCLMULQDQ), and VBROADCASTSS/SD/F128, VINSERTF128, VEXTRACTF128, VPERMILPS/PD, VPERM2F128, VMASKMOVPS/PD, VTESTPS/PD, VBLENDVPS/PD with is4, VZEROUPPER and VZEROALL; CPUID reports AVX. The semantics reuse the pure kernels of `Simd.lean`, `Ext/Sse.lean` and `Ext/Crypto.lean` on (VEX.vvvv, r/m), per 128-bit lane for VEX.256. `Vex.lean` is the shared layer for the AVX2 work: #UD unless CR4.OSXSAVE and XCR0[2:1] = 11b, #NM with CR0.TS (CR0.EM and CR4.OSFXSR do not apply), the per-instruction VEX.L/VEX.W/VEX.vvvv/ModRM.mod #UD rules first; VEX.128 writes zero bits 255:128; only the explicitly aligned moves fault on misaligned operands (16 or 32 bytes, also with MXCSR.MM); #AC at CPL 3 for operands not aligned to min(size, 16); SIMD exceptions through `sseStatus`. Choices: VMASKMOVPS/PD never access masked-out elements (Intel's rule; AMD calls it implementation dependent), VEX.W is ignored by VZEROALL and by the 32-bit forms of VMOVD/VPEXTRD/VPINSRD/VCVTSI2Sx, imm8[7] of is4 and the inverted VEX.vvvv[3] of C4 are ignored outside 64-bit mode, and VMOVSS/VMOVSD loads ignore VEX.vvvv (both manuals require 1111b only for the store form). With AVX reported, Linux enables the YMM state ("Enabled xstate features 0x7, context size is 832 bytes"); the boot and workload are unchanged.
- The XSAVE feature set (`X86/Ext/Xsave.lean`): CR4.OSXSAVE (mirrored in CPUID 1:ECX[27] with both identities), XCR0 with XGETBV (ECX = 1: XCR0 AND XINUSE) and XSETBV (CPL 0, only XCR0 = 1, 3 or 7), XSAVE, XRSTOR, XSAVEOPT, XSAVEC, XSAVES and XRSTORS in the standard and compacted formats with every header, alignment, #UD/#NM/#GP/#PF rule of the SDM/APM, IA32_XSS (no supervisor component on the 7742) and CPUID leaf 0xD. State components: x87, SSE and the AVX state YMM_Hi128 (`SseState.ymmh`), which XCR0[2] can enable before the AVX instructions exist; PKRU, which the 7742's leaf 0xD lists without PKU, is not reported (`Cpuid.xcr0Supported`). Where hardware has latitude the model is exact: XINUSE[i] is set by XRSTOR loading component i and while i is outside its initial configuration, and cleared by XRSTOR initializing it; the modified optimization applies only to an XSAVEOPT/XSAVES directly after the XRSTOR/XRSTORS with the same CPL, address and XCOMP_BV. With XSaveErPtr (CPUID 8000_0008:EBX[2]: "FXSAVE, XSAVE, FXSAVEOPT, XSAVEC, XSAVES always save error pointers", AMD APM vol. 3, appendix E) XSAVE* write the x87 error pointers like FXSAVE, with or without a pending exception, and XRSTOR* always load them. Linux now saves its FPU state with XSAVES ("Enabled xstate features 0x3, context size is 576 bytes, using 'compacted' format").

- AVX2, FMA3 and F16C (`X86/Ext/Avx2.lean`, built on `Vex.lean` and AVX's kernels): the VEX.256 forms of every packed-integer instruction (per 128-bit lane where the SDM/APM say so: PSHUFB, PALIGNR, PACK*, PUNPCK*, PHADD*, PSLLDQ, PBLENDW, VMPSADBW with imm8[5:3] for the upper lane; the shifts by an XMM count use one 64-bit count for both lanes; VPMOVSX/ZX widen across the register), VPERMD/PS/Q/PD, VPERM2I128, VINSERTI128/VEXTRACTI128, VBROADCASTI128, VPBROADCASTB/W/D/Q and VBROADCASTSS/SD from a register, VPBLENDD, VPSLLV/VPSRLV/VPSRAVD, VPMASKMOVD/Q (masked-out elements never accessed, stores checked before any write), VMOVNTDQA/VPMOVMSKB ymm, and the eight gathers with VSIB addressing (#UD for ModRM.mod = 11b, no VSIB byte, 16-bit addressing and any two of destination/mask/index equal; elements in ascending order, each with its segment, #AC (element size) and paging checks; a fault keeps the loaded elements with their mask elements cleared, the one change outside the module being that `Step.faultCpu` keeps the vector registers of a faulting gather; on completion the mask is zero and the unused destination bits are cleared). FMA3: all 132/213/231 forms of VFMADD, VFMSUB, VFNMADD, VFNMSUB (PS/PD/SS/SD) and VFMADDSUB/VFMSUBADD on `FP.fma`, an exact fused multiply-add with one rounding (MXCSR.RC, DAZ, FTZ with tininess after rounding, all flags); NaN operands are chosen in the order x, y, z of x·y + z, and 0·∞ + QNaN returns the QNaN without IE (SDM vol. 1 table 14-17; AMD's manuals are silent, an open question for the native campaign); scalar forms keep bits 127:32/64 of the destination. F16C: VCVTPH2PS (exact; DAZ ignored, no DE, as AMD documents) and VCVTPS2PH (imm8 or MXCSR rounding, FTZ ignored, register or memory destination) on a binary16 format in `Float.lean`. Zen 2 has no FMA4: VEX.0F3A 5C..5F, 68..6F, 78..7F are #UD. Choices where the manuals leave room are listed in the module documentation (VPMASKMOV #AC at 16-byte alignment, no normalization of unprocessed gather mask elements after a fault, data breakpoints of earlier gather elements not delivered in place of a later fault). CPUID reports AVX2, FMA and F16C; Linux boots and runs the workload unchanged.

Not modelled (execution stops with `Fault.unsupported`, or the feature is absent): 64-bit mode (the x86-64 model's; see Long mode above), VAES, 256-bit VPCLMULQDQ, AVX-512 and later (#UD), machine-check errors (CR4.MCE and the MCA MSRs exist, nothing raises #MC; with CR4.MCE = 0 a machine check would shut the processor down, AMD APM vol. 2, 9.4), scalable MCA, the shutdown state (a triple fault stops the simulation; AMD lets an NMI, INIT or RESET restart the processor), TSC-deadline mode (Zen 2 has none), thermal, performance-counter and extended-LVT interrupt sources, the RTC's interrupts.

## Files
- `X86/Word.lean`, `State.lean`: operand sizes, bit names, CPU state.
- `X86/Machine.lean`: physical memory and APIC decoding, paging (32-bit and PAE), TLB, breakpoint matching, segmentation checks, the semantic monad `M`.
- `X86/Decode.lean`, `Alu.lean`, `Exec.lean`: decoder (one-byte, 0F, 0F 38, 0F 3A maps and VEX), flags and arithmetic, instruction semantics.
- `X86/Cpuid.lean`: table-driven CPUID with the leaves of an EPYC 7742, reporting only the implemented features (`implemented`); the identity is still the former one (`identity := .legacy`).
- `X86/Ext/LongModeBase.lean`: long mode's activation rules, 64-bit IDT and call gates, SYSCALL and the 64-bit boundary (imported by `Sys.lean`).
- `X86/Dispatch.lean`, `X86/Ext/*.lean`: instruction dispatch with hooks into one module per extension workstream (stubs today); see [`EXTENDING.md`](EXTENDING.md).
- `X86/Float80.lean`, `Transcendental.lean`, `Fpu.lean`: extended-precision arithmetic, transcendental functions and x87 instructions.
- `X86/Float.lean`, `Simd.lean`: binary32/64 arithmetic, MMX, SSE, SSE2 and FXSAVE.
- `X86/Sys.lean`, `Step.lean`: descriptors, task switches, gates, interrupt delivery, virtual-8086 mode, one architectural step (including debug traps).
- `X86/Dev.lean`, `Io.lean`, `Boot.lean`: devices (local APIC, I/O APIC), port bus and IRQ routing, Linux boot setup and MP tables.
- `X86/Mp.lean`: several CPUs and their scheduler; `X86/Ext/Smp.lean`: the x2APIC MSRs.

## Proofs
`lake build X86Proofs` (or `./verify.sh`, which also rejects `sorry`). The theorems cover ALU results and flags against `BitVec`, every condition code after `CMP`, shifts, IMUL overflow, DIV/IDIV including exactly when #DE is raised, register aliasing, segment and page permission checks, execute-disable (`paeAllowed_nx`: with NXE, no fetch from a page with XD set at any level; `translate_hit_nx`: the TLB never satisfies such a fetch), that disabled breakpoints have no effect (`dbData_disabled`), that call gates enforce their DPL (`callGate_dpl`), that virtual-8086 code runs at CPL 3 (`cpl_vm86`), that RSM is #UD outside SMM (`rsm_outside_smm`), that CR0.EM/TS make every ESC instruction fault with #NM before touching state (`fpCheck_nm`), that FSIN/FCOS/FPTAN/FSINCOS with |x| ≥ 2^63 leave the register stack untouched and set C2 (`fpTrig_out_of_range`), the exact transcendental cases (`f2xm1_one`, `trigFinite_zero`) and that F2XM1 outside its domain is invalid (`f2xm1_out_of_domain`), that SSE instructions are #UD while CR4.OSFXSR is clear (`sseCheck_noosfxsr`) and MMX instructions #UD/#NM with CR0.EM/TS (`mmxPre_em`, `mmxPre_ts`), that every MMX instruction leaves TOP = 0 with all registers valid (`mmxCheck_ok`), that EMMS empties them (`emms_empty`) and that an MMX write sets the exponent word to all ones (`setMm_reg`), that the APIC only presents interrupts above the processor priority (`apic_pending_above_ppr`), and the 15-byte instruction limit. For the general-purpose extensions (`Proofs/ExtGpr.lean`): the population count, TZCNT and LZCNT locate the right bits, BZHI/BEXTR keep the right field, CRC32 computes CRC-32C, MONITOR/MWAIT are #UD at CPL 3 and MWAIT without a monitor does not wait, RDPRU/RDPMC/MCOMMIT enforce CR4.TSD/CR4.PCE/EFER.MCOMMIT, every BMI instruction with VEX.L = 1 is #UD, and RDRAND sets exactly CF. For SSE3..SSE4a (`Proofs/ExtSse.lean`): MXCSR.MM never lifts the alignment #GP of the strict instructions and with MM = 0 every misaligned operand is #GP (`misalignExc_*`), XMM forms #UD without CR4.OSFXSR, PTEST flags, INSERTQ/EXTRQ field round trip, ROUND* precision suppression, the PCMPxSTRx CF/OF definitions and FISTTP never rounding up. For the system extensions (`Proofs/ExtSys.lean`): with SMEP no supervisor fetch from a user page and with SMAP no supervisor data access to a user page except an explicit one with EFLAGS.AC = 1 (`smAllowed_smep`, `smAllowed_smap`, `smAllowed_smap_implicit`), also through the TLB (`translate_hit_smep`, `translate_hit_smap`) and in the walk of a 4 MiB page (`walk32_large_smep`); UMIP's #GP(0) (`umipCheck_gp`); SYSENTER/SYSCALL enter CPL 0 with interrupts disabled and SYSEXIT/SYSRET return to CPL 3, with their #UD/#GP conditions (`sysenter_cpl0`, `sysexit_cpl3`, `syscall_cpl0`, `sysret_cpl3`, ...); CLAC/STAC are #UD at CPL > 0; #AC only for misaligned CPL-3 accesses with CR0.AM and EFLAGS.AC (`acChk_*`); and `cpuid_former` gives CPUID for every leaf and subleaf.

For system workstream B (`Proofs/ExtSysB.lean`): the double-fault classification as decidable statements over every vector (`excClass_spec`, `onSecond_table`: AMD's table 8-3), a fault while delivering #DF shuts down and a contributory fault while delivering a contributory exception gives #DF (`raiseExcF_triple`, `raiseExcF_double`), no NMI is taken while blocked or in an interrupt shadow and SMI > NMI > INTR (`nextEvent_nmi_blocked`, `nextEvent_nmi_shadow`, `nextEvent_smi_first`, `nextEvent_nmi_before_intr`), a completed IRET unblocks NMIs (`execInstr_iret_unblocks`), CLI, STI, POPF, IRET and a redirected INT n cannot change EFLAGS.IF at CPL 3 with IOPL < 3 with or without VME/PVI (`cli_if_cpl3`, `sti_if_cpl3`, `popfMask_if_cpl3`, `vmePopFlags_if`, `vmeIntFlags_if`), VME applies only at CPL 3 (`vmeActive_cpl3`), IRPerfCount holds still while disabled and PATCH_LEVEL is read-only with the AMD identity.

For the crypto instructions (`Proofs/ExtCrypto.lean`): the S-box tables equal the FIPS-197 definition (inverse in GF(2^8) and affine map), MixColumns/InvMixColumns, ShiftRows/InvShiftRows and SubBytes/InvSubBytes are mutually inverse, and for every key schedule the equivalent inverse cipher built from AESDEC/AESDECLAST/AESIMC inverts the cipher built from AESENC/AESENCLAST (`decrypt_encrypt`); the prefix/#UD/#NM rules; and, checked by the kernel (`decide +kernel`, no `native_decide`), the FIPS-197 AES-128/192/256 vectors with the key expansion done by AESKEYGENASSIST, the FIPS 180-4 SHA-1 and SHA-256 example digests composed from the SHA instructions, and GCM test case 2 with GHASH composed from PCLMULQDQ. Carry-less multiplication identities (commutativity, distributivity, shifts) are checked on samples only.

For AVX (`Proofs/ExtAvx.lean`): `Vex.vexCheck` raises #UD without CR4.OSXSAVE or XCR0[2:1] = 11b and #NM with CR0.TS before touching state, ignores CR0.EM, and an encoding violation is #UD first; every VEX.128 destination write zeroes bits 255:128 while legacy SSE writes keep them; VZEROUPPER and VZEROALL have exactly their effect; a VMASKMOVPS/PD store with no selected element changes nothing and cannot fault, a load writes zeros without a memory access; VEX.256 of the integer opcodes is left to the AVX2 hook.

For AVX2, FMA3 and F16C (`Proofs/ExtAvx2.lean`): a gather is #UD before touching state when two of its destination, mask and index registers coincide, for the register form and with 16-bit addressing (`gather_ud_*`); a gather whose mask selects nothing makes no memory access and clears the mask (`gather_zero_mask`); the hooks route VEX.0F38 90..93 to the gather and no hook takes an FMA4 opcode (`vexExec_fma4`); VPSHUFB/VPALIGNR/the 0F-map integer forms act per 128-bit lane (`pshufb256_lanes`, `palignr256_lanes`, `int256_lanes`) while the shifts by an XMM count use one count (`shiftXmm_count`); `FP.fma` returns the first NaN of x, y, z quieted and signals IE exactly for SNaNs, so 0·∞ + QNaN is not invalid (`fma_nan_a`, `fma_nan_b`, `fma_nan_c`), and a table of special and exactly rounded cases (invalid 0·∞ and ∞ − ∞, signed zeros of exact sums in every rounding mode, single rounding, no intermediate overflow, DAZ/FTZ and tininess after rounding) is checked by the kernel (`fma_table`); binary16 → binary32 → binary16 is the identity (without flags) on all 65,536 binary16 encodings except that SNaNs come back quieted, checked exhaustively by the kernel (`halfRoundTrip`, `decide +kernel`). That the FMA's single rounding equals the correctly rounded exact value is by construction (`pack` of the exact integer sum) and checked against Python's `math.fma` and exact rational arithmetic, not proved in general.

For XSAVE (`Proofs/ExtXsave.lean`): CPUID 1:ECX.OSXSAVE equals CR4.OSXSAVE with both identities, leaf 0xD, XSETBV accepts exactly XCR0 = 1, 3, 7 (`xcr0Valid_iff`) and raises #UD/#GP(0) by its rules, every XSAVE-family instruction is #UD without CR4.OSXSAVE, #NM with CR0.TS and (XSAVES/XRSTORS) #GP(0) outside ring 0 before touching any state, misaligned areas are #GP(0), and components outside their initial configuration are tracked as in use.

For long mode (`Proofs/ExtLongMode.lean`): MOV CR0 always leaves EFER.LMA = LME ∧ PG (`movToCr0_lma`) and an accepted EFER write keeps it (`lmaInv_efer`), the #GP(0) conditions of table 14-5 (`movToCr0_nopae`, `movToCr0_csl`, `movToCr4_pae`, `eferOk_lme`, `eferOk_lma`); 4-level permission combination: a user access needs U/S = 1, a write R/W = 1 (unless a supervisor write with WP = 0) and, with NXE, a fetch NX = 0 at every level, a supervisor fetch with SMEP U/S = 0 at some level (`longCheck_user`, `longCheck_write`, `longCheck_nx`, `longCheck_smep`), and every successful 4-level walk passed that check (`walkLong_check`); in 64-bit mode the decoder fetches nothing and the step stops (`decode_64bit`, `execInstr_64bit`); SYSENTER/SYSEXIT are #UD in long mode (`sysenter_long`, `sysexit_long`) and SYSCALL from compatibility mode enters 64-bit mode at CSTAR (`syscall_long`). The TLB theorems (`translate_hit_nx`, `translate_hit_smep`, `translate_hit_smap`) hold in every paging mode, and `walk_long` states that with PAE and LMA the walk is the 4-level one.

For the multiprocessor platform (`Proofs/ExtSmp.lean`): with one CPU the scheduler is exactly the single-CPU step for any number of steps (`MpMachine.steps_single`), a CPU waiting for STARTUP executes nothing and takes no interrupt, NMI or SMI (`step_waitSipi`) and is never scheduled (`runnableState_waitSipi`), the scheduler switches only to a runnable CPU, the invalid IA32_APIC_BASE writes and x2APIC transitions are #GP(0) (`apicBaseWr_*`), the x2APIC MSRs are #GP(0) outside x2APIC mode, a software-disabled APIC accepts no fixed interrupt, a masked I/O APIC pin delivers nothing, and the MP floating pointer's checksum; `physRd_none`/`physWr_none` now exclude both device pages; `apic_pending_above_ppr` is unchanged.

For the platform review fixes (`Proofs/ExtPlatform.lean`): INIT keeps a STARTUP accepted while it was pending (`initCpu_sipi`, `recv_init_sipi`), INIT clears R11/RIP and RSP high halves/EFER and keeps CD/NW and the x87 state, APs start with RESET's CR0 and x87 control word (`afterInit_*`, `atReset_*`), RSM sets LMA = LME ∧ PG ∧ PAE and with its shutdown check LMA = LME ∧ PG, and never changes SVME (`rsmEfer_*`), EOI leaves TMR alone (`eoiVec_tmr`), I/O APIC entries in SMI/NMI/INIT/ExtINT mode are never level-triggered (`levelEntry_mode`, `ioapicService_edge`), and the scheduler's fast path is its step (`stepRunning_eq`, `idle_runnable`).

These are selected properties; the floating-point engines do not yet have a complete proof of arithmetic and rounding correctness.

Most proofs use `bv_decide`, which adds one axiom per theorem that trusts Lean's compiled LRAT checker.

## Multiprocessor model

`X86/Tso.lean` retains the x86-TSO store-buffer model and its proofs. MFENCE drains the buffer;
non-temporal and masked stores, APIC MMIO, SMM, paging and I/O remain outside its supported scope.
The sequential multiprocessor `MpMachine` (`X86/Mp.lean`) is a different, deterministic model of several CPUs; the two are kept apart. Its contract: the running CPU is held in the same `Machine` fields as a single CPU, so with N = 1 a step is exactly the single-CPU `step` (`MpMachine.steps_single`); with N ≥ 2 CPUs take turns round robin with a fixed quantum (1000 steps by default, `x86run --quantum`, `x86sys --quantum`), halted and waiting CPUs are skipped, and one virtual clock (`icount`) counts the instructions of all CPUs, skipping ahead only when every CPU idles; the quantum selects only among timings hardware permits (see `X86/Mp.lean`, "Determinism contract": a CPU that does not run behaves as one stalled in an instruction; APIC-side effects — IRR/TMR, STARTUP acceptance, timers, arbitration, I/O APIC remote IRR — and MWAIT wake-ups by any store are exact at every instruction), and the SMP Linux boot gives the same transcript for quanta 100 to 1,000,000; all TSCs are that clock plus their own offset (synchronized), and per-CPU instruction counts are kept for statistics. Each instruction executes within one step of one CPU on a single memory, so every instruction (LOCKed or not) is atomic and the memory order is sequentially consistent, stronger than x86-TSO; MWAIT ends when another CPU changes the monitored line (checked at quantum boundaries).
Build the separate library with `lake build X86Tso`; [`../validation/litmus/`](../validation/litmus/README.md)
contains its concurrency tests.
