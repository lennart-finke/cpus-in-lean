# IA-32

A model of 32-bit x86 as pure Lean definitions. The proofs in `X86/Proofs/` are about the same definitions that are compiled to boot Linux 6.12.111 (see [`../validation/`](../validation/README.md)); there is no separate emulator that could drift from the specification.

It models **32-bit mode on an AMD EPYC 7742** (Zen 2, family 17h model 31h stepping 0): legacy protected, real and virtual-8086 mode, and 32/16-bit code in compatibility mode, with the 7742's instruction set as far as 32-bit code can use it, its system features, SVM, and up to 128 logical CPUs. CPUID reports the 7742's identity ("AuthenticAMD", signature 00830F10h, "AMD EPYC 7742 64-Core Processor", the leaves of a real 7742's CPUID dump) and exactly the feature bits the model implements: 124 of the dump's 162 ([`CPUID.md`](CPUID.md) gives the reason for each of the 38 masked ones). 64-bit code is not executed (`../x86_64/` is a separate model). Linux 6.12 boots on it as on a 7742 ("CPU: AMD EPYC 7742 64-Core Processor (family: 0x17, model: 0x31, stepping: 0x0)", SYSENTER system calls, XSAVEC, MWAIT idle) in about 54M instructions (≈ 13 s).

It is checked against QEMU's TCG (EPYC-Rome), independent Python references, Linux, and a real EPYC 7742: the integer core in earlier native campaigns, every user-mode family of the Zen 2 work in all 189,216 cases of the user-mode hardware bundle, where the model agrees with the processor except for the documented approximations (RCPPS/RSQRTPS and their VEX forms, 8 transcendental results within 0.6 ulp). The privileged features have not run on the processor yet (KVM harness; [`../validation/README.md`](../validation/README.md), "Hardware tests"). Where the hardware differs from the manuals or from QEMU, the model follows the hardware.

## What's modelled
- The integer instruction set (≈ 330 opcodes), including BCD, string instructions with REP, CMPXCHG8B, CMOV, CPUID, RDTSC and MSRs.
- Segmentation, protection rings, interrupts and exceptions through the IDT, far control flow, port I/O with the TSS permission bitmap.
- Call gates (16- and 32-bit; inner-privilege calls switch stacks and copy parameters) and hardware task switching (JMP/CALL to a TSS or task gate, IDT task gates, IRET with NT, 32- and 16-bit TSSs, the T flag); a fault after the switch has committed is delivered in the new task.
- Virtual-8086 mode with CR4.VME and CR4.PVI (AMD APM vol. 2, 8.8-8.10): IOPL-sensitive instructions, VIF/VIP with CLI/STI/PUSHF/POPF/IRET at IOPL < 3 (with the #GP(0) rules for VIP and TF), and INT n redirected through the TSS interrupt redirection bitmap (table 8-11).
- Two-level paging (4 KiB and 4 MiB pages, A/D bits, CR0.WP) and PAE paging (PDPTE registers, 2 MiB pages, reserved-bit faults, execute-disable with EFER.NXE), with a 1024-entry TLB that software must flush, as on hardware.
- Debug registers: instruction, data and I/O breakpoints, single-step, general detect, RF, and debug traps held across MOV SS / POP SS (so `MOV SS; INT n` takes the #DB at the handler entry, the behaviour behind CVE-2018-8897).
- The x87 FPU (`X86/Float80.lean`, `X86/Fpu.lean`): exact 80-bit arithmetic with rounding and precision control, denormals, x87 NaN rules, masked and unmasked exception responses (#MF, FERR#), every instruction and memory format including BCD, the environment and FNSAVE/FRSTOR formats (the reserved upper halves of the 32-bit protected-mode layout stored as FFFFh), and FIP/FDP/FOP. As on the 7742: the stack-fault priorities of FLD ST(i) and FXTRACT; FCOM/FUCOM/FTST/FCOMI/FUCOMI write their result also when IE or DE is unmasked; control-word bits 7 and 13..15 read as 0, bit 6 as 1; an SNaN m32/m64 operand is not quieted before the NaN choice (with a QNaN ST(0), ST(0)'s QNaN wins). FST/FSTP m32/m64 report no DE (SDM; QEMU sets it).
- The x87 transcendental instructions (`X86/Transcendental.lean`, which describes the engine): F2XM1, FYL2X, FYL2XP1, FPATAN, FSIN, FCOS, FSINCOS and FPTAN return the correctly rounded value of the exact function in the current rounding mode, within the SDM's bounds (below 1 ulp, 1.5 ulps in directed modes; vol. 1, 8.3.10), computed in ball arithmetic (Ziv's strategy). FSIN, FCOS, FSINCOS and FPTAN reduce exactly by Pi/2 with the nearest quotient, Pi being the SDM's 66-bit 0.C90FDAA22168C234C·2^2 (vol. 1, 8.3.8): |x| ≤ Pi/4 gives sin x itself, larger arguments sin(x + k(π − Pi)/2), the SDM's sin(x·π/Pi). |x| ≥ 2^63 sets C2 and leaves ST(0) unchanged. Where the SDM leaves the result undefined the model does what the EPYC 7742 does: F2XM1 returns a finite x with |x| > 1 unchanged with PE, +∞ for +∞ and −1 for −∞; FYL2XP1 computes y·log2(1 + x) for every x > −1 (also outside AMD's documented range √2/2 − 1 ≤ x ≤ √2 − 1) and returns x with PE for x ≤ −1 (special operands: rules below); F2XM1, FYL2X and FYL2XP1 report PE for every finite nonzero result, also an exact one, and F2XM1(+1) is the rounding of a value just below 1. The hardware's results differ from the correctly rounded ones in 8 of 3,376 compared cases, by 1 ulp (its error at most 0.58 ulp).
- MMX, SSE and SSE2 (`X86/Simd.lean`, `X86/Float.lean`): MM0–7 aliased to the x87 registers (TOP = 0, tags valid, exponent word all ones), XMM0–7 and MXCSR with exact binary32/binary64 arithmetic (rounding modes, DAZ, FTZ, all six flags, unmasked exceptions as #XM or #UD), every instruction, mandatory-prefix decoding (undefined combinations are #UD), 16-byte alignment checks, FXSAVE/FXRSTOR, fences and non-temporal stores. RCPPS/RSQRTPS use the EPYC 7742's tables (rules below). With alignment checking, FXSAVE raises #AC for an operand not 4-byte aligned before the 16-byte #GP(0); MASKMOVQ/MASKMOVDQU check 8-byte alignment (EPYC 7742).
- SSE3, SSSE3, SSE4.1, SSE4.2, SSE4a and AMD's Misaligned SSE mode (`X86/Ext/Sse.lean`): every instruction, as pure kernels on 128-bit values that the AVX forms reuse; ROUND* uses an exact round-to-integral (`FP.roundToIntegral`). HADDPx/HSUBPx return the lower element's NaN of a two-NaN pair (EPYC 7742; the manuals add the higher element first). MXCSR.MM (bit 17) lifts the 16-byte alignment #GP of legacy load/execute instructions (not of MOVAPx, MOVDQA, MOVNTPx, MOVNTDQ, MOVNTDQA, FXSAVE/FXRSTOR), raising #AC instead under alignment checking; MXCSR_MASK is 0x2FFFF. Undefined results, as on the EPYC 7742: EXTRQ/INSERTQ clear bits 127:64 (QEMU and Bochs keep them) and read bits above 63 as zero when index + length > 64; the equal-ordered PCMPxSTRx mode follows the SDM where AMD's pseudo code differs.
- The general-purpose Zen 2 extensions (`X86/Ext/Gpr.lean`): POPCNT, LZCNT, TZCNT, BMI1/BMI2, ADCX/ADOX, MOVBE, CRC32, RDRAND/RDSEED (a deterministic SplitMix64 source in machine state; they never fail), RDTSCP/RDPID, RDPMC, RDPRU (MPERF/APERF at the TSC rate), CLFLUSH/CLFLUSHOPT/CLWB (the checks of a one-byte load), CLZERO, WBNOINVD, PREFETCH/PREFETCHW, MCOMMIT and MONITOR/MWAIT/MONITORX/MWAITX (MWAIT waits like HLT for an interrupt, with ECX[0] also a masked one, while the armed 64-byte line is unchanged; HWCR.MonMwaitUserEn allows them at CPL 3). RORX with VEX.vvvv ≠ 1111b is #UD (the SDM's rule and the EPYC 7742's; the APM lists none); RDPRU with an unsupported ECX returns 0. The undefined flags are the 7742's: LZCNT/TZCNT keep OF and clear SF, AF, PF; ANDN/BLSx/BZHI clear AF and set PF from the result; BEXTR sets AF = 1, SF = 0, PF from the result.
- System extensions (`X86/Ext/Sys.lean`, paging in `X86/Machine.lean`): SYSENTER/SYSEXIT, AMD's legacy-mode SYSCALL/SYSRET (SYSRET keeps SS's cached attributes and does not force its RPL), CLAC/STAC, SMEP and SMAP (implicit supervisor accesses to the GDT, LDT, IDT and TSS are checked regardless of EFLAGS.AC, as the APM says), UMIP, global pages, PSE-36, MAXPHYADDR 48 (memory above 4 GiB is open bus), alignment checking (#AC with CR0.AM and EFLAGS.AC at CPL 3, the operand alignments of the APM's table 8-7, checked before paging; implicit accesses and instruction fetches exempt), AltMovCr8, EFER.FFXSR, TCE, LMSLE and INTWB (accepted; without effect in legacy mode), and the MSRs: TSC, SYSENTER/SYSCALL, PAT, MTRRs, MCG_CAP/STATUS/CTL and 23 MCi banks, SPEC_CTRL, PRED_CMD, SYSCFG, IORRs, TOP_MEM/TOP_MEM2, NB_CFG, the watchdog timer, OSVW, the CPUID override MSRs (storage only), LS_CFG and DE_CFG. Values that need the family 17h PPR are marked UNCONFIRMED.
- AES-NI, PCLMULQDQ and the SHA extensions (`X86/Ext/Crypto.lean`): pure functions on 128-bit values, reused by the VEX forms, under the SSE rules. A wrong mandatory prefix is #UD, including 66/F2/F3 on the "NP" SHA instructions, and the SHA instructions accept a misaligned m128, both as on the EPYC 7742 (QEMU's TCG runs the prefixed forms; the SDM lists exception class 4).
- Long mode (`X86/Ext/LongModeBase.lean`, `X86/Ext/LongMode.lean`, `walkLong` in `X86/Machine.lean`; their documentation lists every difference from legacy mode): LMA = LME ∧ CR0.PG with the checks of APM vol. 2 table 14-5; 4-level paging with 1 GiB pages in the same TLB; compatibility mode for 32- and 16-bit code (64-bit IDT and call gates, no task switching or virtual-8086 mode, SYSCALL to CSTAR, SYSENTER/SYSEXIT/SWAPGS/RDFSBASE.. #UD, FS_BASE/GS_BASE/KernelGSbase). CMPXCHG16B, a 64-bit-mode instruction the x86-64 model lacks, is not reported. **The 64-bit boundary**: no instruction executes in 64-bit mode (CS.L = 1 with LMA, theorem `execInstr_64bit`); every transfer into 64-bit code (far JMP/CALL/RET, IRET, SYSCALL, every interrupt or exception in long mode) executes completely, with all its checks and stack writes, and the next step stops with `Fault.unsupported "64-bit mode"`, with RIP/RSP bits 63:32 and R11 in `LongModeState`: a complete 64-bit state that `validation/BridgeMain.lean` hands to the x86-64 model. DR0–DR3 hold 32-bit addresses, so stack slots at or above 4 GiB match no breakpoint; the first 64-bit instruction's instruction-breakpoint check is left to the 64-bit executor. Not modelled: a #PF on a 64-bit stack above 4 GiB (CR2 is 32 bits; the model stops).
- System-management mode: SMIs through the APM control port (0xB2; to the CPU executing the OUT — which CPUs a real chipset signals is open), the AMD64 SMRAM state-save map (APM vol. 2, table 10-1) with EFER (so SMIs are taken in long mode too), SMM entry with EFER = 0, RSM with the shutdown checks of 10.4, SMBASE relocation.
- NMI, exception classes and IRPerf (`X86/Ext/SysB.lean`, `X86/Step.lean`): one latched NMI per CPU (`Cpu.latchNmi`) from every APIC NMI source (plus a model-only test MSR used by `x86sys`); NMIs blocked until an IRET completes (APM vol. 2, 8.1.4: a faulting IRET leaves them blocked, unlike the Intel SDM) and in SMM, and held in the MOV SS/STI shadow; boundary events in the priority order of AMD's table 8-9 (SMI, debug traps, NMI, INTR; `Step.nextEvent`); the double-fault classes of AMD's tables 8-2/8-3 and the EXT bit of error codes; IRPerfCount (C000_00E9h); HWCR.McStatusWrEn for the MCi_STATUS MSRs; MSR 8Bh read-only (#GP on WRMSR) with the AMD identity (PATCH_LEVEL) and writable with the legacy Intel identity, where Linux writes it while booting.
- PIC, PIT, UART, CMOS RTC and the Linux 32-bit boot protocol (with MP tables for `--smp`).
- The multiprocessor platform (`X86/Dev.lean`, `Machine.lean`, `Io.lean`, `Mp.lean`, `Ext/Smp.lean`; APM vol. 2, chapter 16): local APICs with every message type and destination mode, AMD's lowest-priority arbitration, the one-shot and periodic timer, the AMD extended APIC space and x2APIC mode; an 82093AA I/O APIC at 0xFEC00000 (24 entries) receiving the PIT, UART and RTC lines alongside the PICs; INIT (`Cpu.afterInit`), wait-for-SIPI and STARTUP; application processors start from the RESET state (CR0 = 6000_0010h, x87 CW 0040h/TW 5555h), which INIT keeps; at most 128 CPUs (one 7742 package), the I/O APIC ID is N for N ≤ 14, else 0, and CPUID reports the topology of the first N threads of a 7742 package (`Cpuid.topo`; for N = 1 HTT and CmpLegacy are 0). `MpMachine` runs the CPUs ([below](#multiprocessor-model)). Choices where the APM is silent or inconsistent are listed in `X86/Dev.lean` (e.g. SVR.FCC, XAIDN, IER writes, SAE).
- Deterministic virtual time: a nominal 100M instructions per second, with HLT skipping to the next timer event.
- AVX (`X86/Ext/Vex.lean`, `X86/Ext/Avx.lean`): YMM0–7 (`SseState.ymmh` holds bits 255:128) and every AVX instruction of Zen 2 in 32-bit mode (VEX.128 AES-NI and VPCLMULQDQ included), on the SSE and crypto kernels per 128-bit lane. `Vex.lean`, shared with AVX2: #UD unless CR4.OSXSAVE and XCR0[2:1] = 11b, #NM with CR0.TS (CR0.EM and CR4.OSFXSR do not apply), encoding #UD first; VEX.128 zeroes bits 255:128; only the explicitly aligned moves fault on misaligned operands (also with MXCSR.MM); #AC at CPL 3 for operands not aligned to min(size, 16). VMASKMOVPS/PD never access masked-out elements (Intel's rule; AMD: implementation dependent). As on the EPYC 7742: VEX.W is ignored by VZEROALL and the 32-bit forms of VMOVD/VCVTSI2Sx, VPEXTRD/VPINSRD with W1 are #UD, a form that needs VEX.vvvv = 1111b checks all four bits, and VMOVSS/VMOVSD loads need it too (the manuals name only the store); further choices are in the module documentation.
- The XSAVE feature set (`X86/Ext/Xsave.lean`): CR4.OSXSAVE, XCR0 with XGETBV (ECX = 1: XCR0 AND XINUSE) and XSETBV (only XCR0 = 1, 3 or 7), XSAVE, XRSTOR, XSAVEOPT, XSAVEC, XSAVES and XRSTORS in the standard and compacted formats, IA32_XSS (no supervisor component on the 7742) and leaf 0xD, for the x87, SSE and YMM_Hi128 components; PKRU, which the 7742's leaf 0xD lists without PKU, is not reported (`Cpuid.xcr0Supported`). Where hardware has latitude (XINUSE, the modified optimization) the model is exact. The x87 error pointers are saved only with FSW.ES = 1, although CPUID reports XSaveErPtr (rules below). Linux on the AMD identity clears XSAVES (AMD erratum 1386, `fix_erratum_1386`) and uses XSAVEC.
- AVX2, FMA3 and F16C (`X86/Ext/Avx2.lean`): the VEX.256 integer forms (per 128-bit lane where the manuals say so; the shifts by an XMM count use one count for both lanes), cross-lane permutes and broadcasts, variable shifts, VPMASKMOVD/Q (masked-out elements never accessed, stores checked before any write) and the eight VSIB gathers (elements in ascending order; after a fault the loaded elements stay, their mask elements cleared, kept by `Step.faultCpu`). FMA3 on `FP.fma`, an exact fused multiply-add with one rounding (MXCSR.RC, DAZ, FTZ with tininess after rounding, all flags); NaNs are chosen in the order x, y, z of x·y + z, and 0·∞ + QNaN returns the QNaN without IE (SDM vol. 1 table 14-17; AMD is silent). F16C: VCVTPH2PS (exact; DAZ ignored, no DE, as AMD documents) and VCVTPS2PH on binary16 in `Float.lean`. Zen 2 has no FMA4: VEX.0F3A 5C..5F, 68..6F, 78..7F are #UD. As on the EPYC 7742, gathers and VPMASKMOV raise no #AC and VPERMQ/VPERMPD ignore VEX.W; the other choices are in the module documentation.
- SVM (`X86/Ext/Svm.lean`, `X86/Ext/SvmBase.lean`, whose documentation gives the scope and choices; APM vol. 2, chapter 15): the SVM MSRs, VMRUN with the full VMCB and every consistency check (VMEXIT_INVALID); every intercept Zen 2 has, at the point table 15-7 gives (FERR_FREEZE where a waiting x87 instruction with CR0.NE = 0 would freeze; the model freezes nothing without it), the I/O and MSR permission maps read like physical memory (open bus above 4 GiB: intercepted); #VMEXIT with exit information, nRIP and decode assists; event injection, GIF, virtual interrupts, SMIs in a guest, SKINIT's CPU-state effects; nested paging in every paging mode; a per-ASID view of the TLB (the host's entries set aside while a guest runs, a guest starts empty). A 64-bit guest stops at the 64-bit boundary, a long-mode guest with CR3/GDTR/IDTR (or a VMLOAD of TR/LDTR) above 4 GiB stops (`Fault.unsupported`, as RSM does), and VMRUN in a 64-bit host is unreachable. Leaf 8000_000A reports revision 1 and 8000h ASIDs; VmcbClean is reported but ignored (every field is loaded).

## Rules taken from the EPYC 7742 (extended native run)

The extended native bundle (863,642 single instructions; [`../validation/README.md`](../validation/README.md), "The extended run") fixed these behaviours, left open or stated differently by the manuals (citations in the code):
- **Lengths of undefined encodings** (`Decode.lean`): the processor decodes the whole length, and raises #GP(0) beyond 15 bytes, before its #UD. XOP (8F with ModRM.reg ≠ 0, any map field): 8F, two bytes, opcode, ModRM/SIB/displacement, an imm32 in map 0Ah only; unknown VEX maps: ModRM, no immediate; 0F 0F (3DNow!) and VEX.0F 0F: ModRM and imm8; 0F 78: its two imm8 whatever the prefix; 0F B9 (UD1) and 0F FF (UD0, also VEX): no ModRM; VEX.0F 80–8F: 4 immediate bytes whatever 66 says. EVEX (62, mod = 11) stays the 2-byte BOUND form.
- **Integer**: MOV to/from CR1, CR5–CR7 is #UD before the CPL check; BSWAP r16 clears bits 15:0; ARPL reads its operand and writes it only when it adjusts the RPL; CMPS reads ES:(E)DI first; LOOPE/LOOPNE with F2/F3 take the condition from the last of them (F3: ZF = 1, F2: ZF = 0); REP INS/OUTS check the I/O permission with a zero count; ENTER writes BP or EBP by operand size and raises #AC for a final stack pointer not aligned to the operand size.
- **Every documented-undefined arithmetic flag** of the integer set has the 7742's value: shifts AF = 1 and OF from the result for every count, RCR OF = bit w−1 XOR bit w−2, SHLD/SHRD (16-bit counts 17..31 rotate the source), MUL/IMUL keep SF/ZF/AF/PF, DIV/IDIV set AF and clear SF/ZF/PF, AAA/AAS from AX ± 106h, DAA/DAS OF, AAD's CF/AF/OF of its addition (the table in `validation/README.md`).
- **x87/MMX/SSE**: EMMS sets TOP = 0; CVTPI2PS m64 leaves the x87 state alone; the MMX transition survives #XM of the MMX conversions and faults of MASKMOVQ; MASKMOVQ/MASKMOVDQU fault at DS:(E)DI; FSW.ES = B = "an unmasked flag is set" on every load (FLDENV, FRSTOR, FXRSTOR, XRSTOR); FNSTENV clears them; FLDCW, FLDENV, FRSTOR wait (#MF); x87 stores check their destination even when an unmasked exception suppresses them, and report no PE with an unmasked OE/UE; FSTP1 (D9 D8+i) with an empty ST(0) only pops; FYL2XP1(+∞, y) = ±∞, FYL2XP1(−1, ±0/±∞) = ∓0/∓∞; FXSAVE/XSAVE write FOP/FIP/FDP only with FSW.ES = 1 (XRSTOR* always load them), zero the register slots' padding, and fault first at the last byte of their area (XRSTOR: its header); FXRSTOR's #AC precedes its #GP; 16-/64-byte alignment #GP precedes a segment-limit fault; VCVTPS2PH checks its memory destination before MXCSR and #XM.
- **RCPPS/RSQRTPS/RCPSS/RSQRTSS** (legacy and VEX): the 7742's 4096-entry tables of 12-bit result fractions (`X86/Zen2Rcp.lean`, generated by `validation/test/zen2_rcp.py` from the native family `sse_rcp_sweep`); the correctly rounded definition is kept as `FP.rcpSpec`/`FP.rsqrtSpec`.

## Boundaries: what is not modelled

- **64-bit code.** No instruction executes in 64-bit mode; the model stops before the first one with a complete 64-bit state (see Long mode and SVM above).
- **ISA the 7742 lacks** (#UD, as on the 7742): AVX-512, VAES, 256-bit VPCLMULQDQ, XOP/FMA4/TBM, PKU, PCID, LA57, TSC-deadline mode, CET.
- **Features of the 7742 that are masked** ([`CPUID.md`](CPUID.md)): the six-counter core PMU extension and the NB/L3 counters (no performance events; the four legacy counters never count), IBS, L3 QoS (PQM/PQE), SME/SEV, the DR address-mask extensions, scalable MCA and MCA recovery, the power-management bits (P-states, boost, RAPL, thermal), PPIN, SVM's LbrVirt and AVIC (GMET is Zen 3), and the XCR0 PKRU component.
- **Machine checks**: CR4.MCE and the legacy MCA banks exist, nothing raises #MC.
- **Shutdown**: a triple fault stops the simulation (AMD lets an NMI, INIT or RESET restart the processor).
- **TPM, DMA protection**: SKINIT has its CPU-state effects only.
- **Devices**: PIC, PIT, UART, CMOS RTC (no RTC interrupts), local APICs and one I/O APIC; no PCI, ACPI, disks or network; no thermal, performance-counter or extended-LVT interrupt sources; SMRAM protection is the chipset's and is not modelled.
- **Timing and caches**: no caches, no speculation; time is the virtual instruction count; hints that need timing (MWAIT C-states, PAUSE, prefetches) have no effect beyond their architectural checks.
- **Concurrency**: `MpMachine` is sequentially consistent, stronger than x86-TSO ([below](#multiprocessor-model)).

Implementation-defined results and choices unconfirmed on a 7742 are marked in the module documentation and listed, with the native case observing each, in "Open questions for the EPYC" ([`../validation/README.md`](../validation/README.md)).

- `X86/Word.lean`, `State.lean`: operand sizes, bit names, CPU state.
- `X86/Machine.lean`: physical memory and APIC decoding, paging (32-bit and PAE), TLB, breakpoint matching, segmentation checks, the semantic monad `M`.

- `X86/Dispatch.lean`, `X86/Ext/*.lean`: instruction dispatch with hooks into one module per extension (Gpr, Sse, Crypto, Xsave, Vex/Avx, Avx2, Sys, SysB, LongModeBase/LongMode, Smp, SvmBase/Svm); [`EXTENDING.md`](EXTENDING.md) is the maintenance guide.
- `X86/Float80.lean`, `Transcendental.lean`, `Fpu.lean`: extended-precision arithmetic, transcendental functions and x87 instructions.
- `X86/Float.lean`, `Simd.lean`: binary32/64 arithmetic, MMX, SSE, SSE2 and FXSAVE.
- `X86/Sys.lean`, `Step.lean`: descriptors, task switches, gates, interrupt delivery, virtual-8086 mode, one architectural step (including debug traps).
- `X86/Dev.lean`, `Io.lean`, `Boot.lean`: devices (local APIC, I/O APIC), port bus and IRQ routing, Linux boot setup and MP tables.
- `X86/Mp.lean`: several CPUs and their scheduler; `X86/Ext/Smp.lean`: the x2APIC MSRs.

## Proofs
`lake build X86Proofs` (or `./verify.sh`, which also rejects `sorry`). These are selected properties; the floating-point engines do not yet have a complete proof of arithmetic and rounding correctness. Most proofs use `bv_decide`, which adds one axiom per theorem that trusts Lean's compiled LRAT checker.

Core: ALU results and flags against `BitVec`, every condition code after `CMP`, shifts, IMUL overflow, DIV/IDIV including exactly when #DE is raised, register aliasing, segment and page permission checks, the 15-byte instruction limit; with NXE no fetch from a page with XD set at any level (`paeAllowed_nx`), also through the TLB (`translate_hit_nx`); disabled breakpoints have no effect (`dbData_disabled`); call gates enforce their DPL (`callGate_dpl`); virtual-8086 code runs at CPL 3 (`cpl_vm86`); RSM is #UD outside SMM (`rsm_outside_smm`); CR0.EM/TS make every ESC instruction #NM before touching state (`fpCheck_nm`); FSIN/FCOS/FPTAN/FSINCOS with |x| ≥ 2^63 set C2 and leave the stack untouched (`fpTrig_out_of_range`); the transcendental domain ends (`f2xm1_one`, `f2xm1_neg_one`, `trigFinite_zero`) and F2XM1 outside its domain (`f2xm1_out_of_domain`, `f2xm1_inf`); SSE is #UD without CR4.OSFXSR (`sseCheck_noosfxsr`), MMX #UD/#NM with CR0.EM/TS (`mmxPre_em`, `mmxPre_ts`); every MMX instruction leaves TOP = 0 with all registers valid (`mmxCheck_ok`), EMMS empties them (`emms_empty`), an MMX write sets the exponent word to all ones (`setMm_reg`); the APIC presents only interrupts above the processor priority (`apic_pending_above_ppr`).

General-purpose extensions (`Proofs/ExtGpr.lean`): POPCNT, TZCNT and LZCNT locate the right bits, BZHI/BEXTR keep the right field, CRC32 computes CRC-32C, MONITOR/MWAIT are #UD at CPL 3 and MWAIT without a monitor does not wait, RDPRU/RDPMC/MCOMMIT enforce CR4.TSD/CR4.PCE/EFER.MCOMMIT, BMI with VEX.L = 1 is #UD, RDRAND sets exactly CF.

SSE3..SSE4a (`Proofs/ExtSse.lean`): MXCSR.MM never lifts the alignment #GP of the strict instructions, and with MM = 0 every misaligned operand is #GP (`misalignExc_*`); XMM forms are #UD without CR4.OSFXSR; PTEST flags; the INSERTQ/EXTRQ field round trip; ROUND* precision suppression; the PCMPxSTRx CF/OF definitions; FISTTP never rounds up.

## Multiprocessor model

`MpMachine` (`X86/Mp.lean`; details in its "Determinism contract") holds the running CPU in the same `Machine` fields as a single CPU, so with N = 1 a step is exactly the single-CPU `step` (`MpMachine.steps_single`). With N ≥ 2 CPUs take turns round robin with a fixed quantum (1000 steps by default, `x86run --quantum`, `x86sys --quantum`), skipping halted and waiting CPUs; one virtual clock (`icount`) counts the instructions of all CPUs, skipping ahead only when every CPU idles, and every TSC is that clock plus its own offset. The quantum selects only among timings hardware permits (a CPU that does not run behaves as one stalled in an instruction); the SMP Linux boot gives the same transcript for quanta 100 to 1,000,000. Every instruction (LOCKed or not) is atomic on a single memory, so the memory order is sequentially consistent, stronger than x86-TSO.

`X86/Tso.lean`, kept apart from `MpMachine`, is the x86-TSO store-buffer model with its proofs. MFENCE drains the buffer; non-temporal and masked stores, APIC MMIO, SMM, paging and I/O are outside its scope. Build it with `lake build X86Tso`; [`../validation/litmus/`](../validation/litmus/README.md) contains its concurrency tests.
